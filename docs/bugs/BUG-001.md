## Reproduction Steps

Initial user-reported path:

1. Open the app.
2. Set target language to Korean.
3. Select the Food topic.
4. Start the voice/playback flow.
5. Repeat with Japanese and a non-sleep topic.

## Expected Result

Playback should speak vocabulary items from the selected target language and selected topic, and include the English meaning according to the selected/native-language playback mode.

## Actual Result

Korean playback repeatedly says `자다`, `자다` and does not include English. Japanese playback also repeatedly says sleep-related vocabulary (`眠` / sleep word) instead of the selected topic vocabulary.

## Severity

High. This affects the core voice playback learning flow.

## Current Status

BLOCKED

## Investigator Conclusion

Investigator Worker completed reproduction-oriented intake. Clean local state did not reproduce BUG-001: Korean + Basic + Food started playback on `밥` and displayed `rice; meal · bap`. The strongest supported root-cause hypothesis is frontend persisted vocabulary state in `localStorage`: `src/main.tsx` merges stored `lingosleep-vocab` over canonical `vocabSeed`, allowing stale/corrupted stored records to override source-of-truth fields such as `targetText`, `reading`, `topic`, and `meanings`.

## Root Cause

Confirmed frontend persistence bug in `src/main.tsx`: stored `lingosleep-vocab` records were merged over canonical vocabulary records, so stale/corrupted browser data could replace canonical fields and cause the selected topic to play sleep vocabulary while omitting English. The Playwright regression seeded corrupted `localStorage` and reproduced the failure for both Korean Food and Japanese Food before the fix.
